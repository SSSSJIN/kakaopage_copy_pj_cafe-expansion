## 🤔 겪었던 어려움 및 해결 과정

### 1. 버전 관리 미숙으로 인한 코드 유실 및 복구 문제
* **문제점**: 프로젝트 초반, Git을 이용한 버전 관리에 익숙하지 않아 중요한 코드 변경 후에도 commit을 자주 누락했습니다. 이로 인해 버그 수정이나 기능 테스트를 위해 이전 상태로 코드를 되돌려야 할 때, 몇 시간 혹은 며칠간의 작업량을 한 번에 잃어버리는 치명적인 문제가 반복적으로 발생했습니다.

* **해결 과정**:

'작업 단위' 분리의 중요성 인지: 코드 유실을 막기 위해, 작업을 더 작고 논리적인 단위로 나누는 습관을 들였습니다. 기능 하나를 통째로 개발한 뒤 한 번에 커밋하는 대신, '로그인 UI 구현', '로그인 기능 처리'처럼 세분화된 작업이 끝날 때마다 즉시 커밋하여 진행 상황을 안전하게 기록하고 관리했습니다.

체계적인 커밋 습관화: 단순히 코드를 저장하는 것을 넘어, **'커밋(Commit)은 미래의 나를 위한 이정표'**라고 생각하며 작업 단위를 논리적으로 분할하여 커밋했습니다. 이를 통해 문제 발생 시 정확한 시점으로 코드를 되돌릴 수 있었고, 프로젝트의 변경 이력을 명확하게 추적할 수 있게 되었습니다.

* **배운 점**: 이 경험을 통해 버전 관리 시스템(VCS)은 단순한 백업 도구가 아니라, 안정적인 개발과 협업을 위한 필수적인 역량임을 깨달았습니다. 체계적인 버전 관리 전략이 개발 생산성을 얼마나 향상시키는지 직접 체감할 수 있었습니다.

### 2. 저작권 문제를 고려한 이미지 리소스 교체

* **문제점**: 초기 기획 단계에서 저작권이 있는 상용 이미지를 사용했으나, 이는 실제 서비스 시 법적 문제를 야기할 수 있는 심각한 리스크였습니다.
* **해결 과정**: 문제 인지 후 즉시 모든 상용 이미지를 제거하고, 상업적 이용이 가능한 라이선스를 가진 **"amazon.books.json" (by dudeonthehorse/datasets)** 데이터셋을 찾아 모든 이미지 리소스를 안전하게 교체했습니다. 또한, README 파일에 데이터 출처와 라이선스를 명확히 고지하여 잠재적 위험을 해소했습니다.
